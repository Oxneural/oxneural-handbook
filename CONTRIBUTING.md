# Contributing to the OxNeural Handbook

This repository holds our engineering standards. Changes to it change how everyone works, so the bar is a little different from a code repository.

## General contribution guidance

The organization-wide guidance in [`.github/CONTRIBUTING.md`](https://github.com/Oxneural/.github/blob/main/CONTRIBUTING.md) applies here — branching, commits, pull requests.

## Changing a standard

Open a pull request and, in the description, state:

1. **What problem this solves.** A standard should exist because something went wrong or nearly did, not because it seemed tidy.
2. **What it changes for people.** Who has to do something differently.
3. **Whether existing repositories need updating.**

Standards changes require review and approval by the founder.

## Principles for writing standards here

- **Write the rule and the reason.** A rule without a reason gets worked around the first time it is inconvenient.
- **Keep it proportionate.** If a rule makes a two-file script harder to ship without making anything safer, it is the wrong rule.
- **Prefer fewer, enforced rules** over many, ignored ones.
- **Be concrete.** "Write good commit messages" is not a standard. A format with examples is.

## Style

Plain English. Short sentences. Tables for anything with more than three cases. Examples of both the right and wrong version — the wrong version is usually what teaches.
